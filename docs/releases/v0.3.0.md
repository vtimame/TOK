## TOK v0.3.0

## Added

- Regression coverage for execution-state invariants now checks run creation
  against open, blocked, in-progress and done tasks.
- A two-connection SQLite regression test verifies that concurrent run creation
  leaves only one active run when active-run override is not requested.

## Changed

- Run creation now requires the task to be `in_progress`; claim the task before
  starting a run.
- `task_block` and `task_unblock` now perform status checks and writes inside a
  single transaction.

## Fixed

- Runs can no longer be created for completed tasks through storage, CLI, MCP or
  HTTP paths.
- Active-run checks now happen atomically with run insertion.
- Block and unblock operations can no longer overwrite a task that became
  `done` concurrently.
- Block and unblock audit events now record the status transition verified in
  the same transaction.

## Migration

- No new storage migration is introduced in this release.
- Existing databases keep their current schema and data; the behavior change is
  enforced in storage and public command/API paths.

## Contract Notes

- CLI: `tok run start`, `tok run exec` and `tok run agent` require the target
  task to be `in_progress`; use `tok task claim` before starting a run.
- MCP: `run_create` requires `task.status == in_progress` and returns a clear
  error otherwise.
- HTTP API: run creation paths now reject tasks that are `open`, `blocked` or
  `done`.

## Validation

- CI: release workflow verifies a successful CI run for the tagged commit before
  publishing assets.
- Local candidate validation: `go test ./...` and `make quality`.
- Release assets: release workflow publishes Linux and macOS archives with
  SHA256SUMS, SHA256SUMS.sigstore.json and GitHub Artifact Attestations.
- SBOM: not included in this alpha.
