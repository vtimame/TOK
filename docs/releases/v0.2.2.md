## TOK v0.2.2

## Added

- Worker MCP profile can read previous runs and run artifacts for persisted handoff.
- Release assets include signed SHA256SUMS via Sigstore bundle.

## Changed

- Task completion uses one canonical evidence flow across CLI, MCP, HTTP, storage, and Web UI.
- `task status ... done` is no longer a supported completion path.

## Fixed

- Web audit trail maps completion evidence to the exact validation artifact recorded on the completion event.
- External task source URLs are validated before storage and before Web UI link rendering.

## Migration

- Existing v0.2.1 databases migrate automatically to add task completion evidence fields and external task source fields.

## Contract Notes

- CLI: use `tok task done <task-id> --note <text> --evidence-run <run-id>` for validated completion, or `--allow-unvalidated --override-reason <text>` for audited override.
- MCP: use `task_done` for completion; `task_status` is for non-terminal status changes.
- HTTP API: use `POST /api/tasks/{id}/done` for completion with evidence or audited override.

- Release assets: Linux and macOS archives published with SHA256SUMS and SHA256SUMS.sigstore.json.
